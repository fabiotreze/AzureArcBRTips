# Security policy

**English** · [Português](#política-de-segurança)

## Reporting a vulnerability

For a suspected vulnerability in this repository, **do not open a public issue** or post exploit details in a pull request.

If private vulnerability reporting is enabled, use **Security → Report a vulnerability** on [GitHub](https://github.com/fabiotreze/AzureArcBRTips/security). If the option is unavailable, contact the maintainer through a private channel you already trust to arrange secure disclosure. Do not post the vulnerability publicly to request contact.

Provide the affected file and version, impact, and sanitized reproduction steps privately. Never include access tokens, credentials, tenant data or environment reports.

Vulnerabilities in Microsoft products or services should be reported to the [Microsoft Security Response Center](https://msrc.microsoft.com/create-report), not to this repository.

## Scope and maintenance

Security reports concern this repository's workbook, deployment template and validation script. Older workbook versions are not maintained separately; reproduce issues on the latest content from `main` when possible. This personal project has no guaranteed response or remediation timeline.

Review artifacts before use, apply least privilege and keep exports and validation reports confidential. A configured security floor is an analysis rule, not a guarantee that a particular agent version is secure.

## Política de segurança

Para suspeitas de vulnerabilidade neste repositório, **não abra issue pública** nem publique detalhes de exploração em pull requests.

Se o reporte privado estiver habilitado, use **Security → Report a vulnerability** no [GitHub](https://github.com/fabiotreze/AzureArcBRTips/security). Se a opção não estiver disponível, procure o mantenedor por um canal privado de confiança que você já conheça para combinar a divulgação segura. Não publique a vulnerabilidade para solicitar contato.

Envie em privado o arquivo e a versão afetados, o impacto e os passos de reprodução sem dados sensíveis. Nunca inclua tokens, credenciais, dados do tenant ou relatórios do ambiente.

Vulnerabilidades de produtos ou serviços Microsoft devem ser reportadas ao [MSRC](https://msrc.microsoft.com/create-report).

O escopo inclui workbook, template de implantação e script de validação. Versões antigas não recebem manutenção separada; quando possível, reproduza o problema no conteúdo mais recente de `main`. Este projeto pessoal não oferece prazo garantido de resposta ou correção.

Revise os artefatos, use menor privilégio e mantenha exportações e relatórios confidenciais. O piso de segurança é uma regra de análise, não uma garantia de segurança de uma versão do agent.
